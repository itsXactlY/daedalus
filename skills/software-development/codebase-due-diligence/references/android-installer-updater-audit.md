# Android Installer / Auto-Updater Audit

Class: Android app that (a) bundles payload APKs and installs them via `PackageInstaller`, (b) has a remote auto-update pipeline (manifest fetch → APK download → SHA verify → session commit), (c) ships via sideload (no Play Store). Reference case: "The Box" in `mazemaker-mobile` (`jackbox/`), audited 2026-08-07 on branch `feat/thebox-autoupdate` (read-only).

## Checklist (verify each; commands proven read-only)

1. **Permissions in the SHIPPED artifact, not the source manifest.** Libraries can add/remove permissions during merge; source can omit them silently.
   - `AAPT2=$(ls ~/Android/Sdk/build-tools/*/aapt2 2>/dev/null | sort -V | tail -1); "$AAPT2" dump badging <published.apk> | grep -E 'package:|uses-permission'`
   - `build/intermediates/packaged_manifests/<variant>/.../AndroidManifest.xml`
   - `git log --all -p -- <path/to/AndroidManifest.xml>` — was the permission ever present?
   - Canonical failure: The Box 1.0.5 shipped with only `REQUEST_INSTALL_PACKAGES, WAKE_LOCK, ACCESS_NETWORK_STATE, RECEIVE_BOOT_COMPLETED, FOREGROUND_SERVICE` — **no INTERNET**. `ACCESS_NETWORK_STATE` allows status queries only, not sockets. Every `HttpURLConnection` threw, was caught, and the whole auto-update feature was dead in every build. Note: `git log --all -p` also tells you the feature was dead on arrival, not regressed.
2. **Background worker actually drains the install flow.** `Flow.first()` returns after the first emission and cancels collection. If the flow emits a status (`Installing`) before network/IO work, `.first()` cancels the work → silent no-op worker. Code comments claiming "we just drain it" can be wrong. Fix: `.collect { }` or a suspend function running to completion. (MainActivity's `collect { }` works; the WorkManager worker using `.first()` does not.)
3. **Manifest trust chain.** Ask: is the remote manifest signed? Is the APK `sha256` self-referential (lives in the same unsigned manifest)? Is there a signing-cert allowlist check before `PackageInstaller` commit? Implicit protections that exist: Android enforces signature match on **upgrade** of already-installed apps; targetSdk ≥ 28 blocks cleartext by default (an `http://` apkUrl fails). Real gap: **first-time installs** (app not installed) accept any APK whose hash is in a compromised manifest. No TLS pinning → CA/server compromise = full payload swap for fresh installs.
4. **Consent/UX:** `installed == null` treated as "pending update" → a background worker would prompt-install apps the user never chose; the UI shows "UPDATE" instead of "INSTALL" for never-installed apps. Separate "update" (installed + newer remote) from "install" (not installed). Never auto-prompt installs of uninstalled apps in a background worker.
5. **versionCode monotonicity / rollback:** manual version bumps; a rebuild with the same versionCode is never pulled by installed devices (`installed < remote.versionCode` is false). Downgrade protection is only that comparison — no explicit rollback guard.
6. **Payload reproducibility:** "LIVE"/checkout-as-is refs + reuse of an existing `app-release.apk` without `REBUILD=1` → non-reproducible builds and stale-artifact shipping. Pin payloads to commits, detect dirty trees (`git status --porcelain`), cache key = commit + dirty-hash.
7. **Payloads in git / Gradle wiring:** if payload APKs + `payloads.json` are gitignored and no Gradle task generates them, a fresh `./gradlew assembleRelease` produces an empty box ("shipped without payloads"). The build script must be part of the build, not a manual pre-step. (Ignoring ½ GB of payloads in git is correct — the gap is the missing Gradle/CI wiring.)
8. **Baked credentials in VM payloads:** grep docs AND rootfs build scripts for default passwords. The Box: podroid rootfs root password `podroid` documented in `docs/FULL_STACK_A_TO_Z.md` + `docs/dev/podroid-vm.md` — every VM instance shares a public root password. Fix pattern: per-install random secret (like the `api_server.key`), key-only auth.
9. **Worktree divergence:** `git worktree list`; `git merge-base A B`; `git log --oneline --left-right A...B`; `git ls-files` inside the worktree vs main checkout; `git diff --stat <merge-base>..<branch>` to enumerate unmerged files. Live branch = main checkout (in sync with origin). Worktree branches can carry unmerged **security fixes** (e.g. "no baked pod key") and whole features (HermesUpstreamConfig.kt, LocalPod*.kt, hermes-config-template.yaml). Also check: shipped payload source ≠ live-checkout source (payload built from a release branch that has files the live branch lacks). Hygiene: `.claude/` (worktree metadata) untracked + unignored → `git add -A` hazard; add to .gitignore.
10. **Docs-vs-code:** grep every documented class/file name against `find <src> -name '*.kt'`; compare README "tech stack" against `build.gradle` dependencies (README claimed Hilt/Firebase/BouncyCastle — none present). Docs may describe an unmerged branch's architecture (docs referenced `LocalPodMcpProxy`, `TAP :8790` — absent from live checkout).
11. **Secrets scan:** `grep -rniE '(api[_-]?key|secret|password|passwd|token|bearer|BEGIN (RSA|EC|OPENSSH|PRIVATE)|sk-[A-Za-z0-9]{20}|AKIA[0-9A-Z]{16})' --include=...` excluding `.git/ build/ dist/`, plus `git log --all -p | grep -i secret`. Positive result: only placeholders (`PASTE_OPERATOR_KEY_HERE`, `storePassword=…`) — no real keys in history.
12. **iOS/TS side-packages:** verify SPM target layout (files outside `Sources/<Target>/` are never compiled), imports (`CC_SHA256` without `import CommonCrypto` won't build), protocol choice (`NWConnection` with `.tcp` is not a WebSocket), and whether crypto modules are actually imported anywhere (an unused "X3DH" that uses ECDSA instead of ECDH and a zero placeholder secret is a landmine, not a feature).

## The Box findings snapshot (2026-08-07)

- CRITICAL: published `TheBox-1.0.5.apk` has no INTERNET permission → auto-update dead; existing installs cannot self-heal (manual reinstall required).
- CRITICAL: `UpdateWorker.kt:28` — `Updater.installUpdate(...).first()` cancels the flow after the `Installing` emission → background updates never run.
- HIGH: manifest unsigned ("signed-ish" KDoc comment is false), SHA self-referential, no cert allowlist, no pinning → first-install path exploitable if relay server compromised.
- HIGH: worktree branch `feat/hermes-upstream-config` 5 ahead / 19 behind, unmerged (incl. security commit `52bb766` "no baked pod key"); published mazemaker-1.4.0 payload built from `release/android-1.4.0` (has `LocalPodHermes/McpProxy`, lacks `HermesUpstreamConfig`) → live source ≠ shipped payload source.
- HIGH: documented root password `podroid` for the VM rootfs.
- MEDIUM: gateway token in plaintext DataStore while device token is in `EncryptedSharedPreferences`; `.claude/` not gitignored; READMEs describe nonexistent files (`McpService.kt`, `AppModule.kt`, Hilt, Firebase...); `installed == null` treated as pending update; no download size limit.
- LOW: iOS SPM package not buildable (`McpModels.swift` outside target, missing `import CommonCrypto`, `.tcp` not WS, no `.xcodeproj`); `src/crypto/jrwl_crypto.ts` "X3DH" is a fake (ECDSA not ECDH, no DH1–4, unused).
