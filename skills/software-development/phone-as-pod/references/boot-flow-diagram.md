# Phone-as-pod boot flow

This is the install-to-ready path for the iris-messenger all-in-one
APK, verified 2026-06-20. Use this as the reference when designing
or debugging a phone-as-pod project.

## Full boot flow (install -> federation ready)

```
User taps iris-android icon (Podroid APK icon)
    |
    v
Podroid VM boots (QEMU TCG or AVF pKVM)
    |  -- QEMU TCG: ~5s, software emulation, no permission
    |  -- AVF pKVM: ~1s, hardware accel, needs 'pm grant' once
    |
    v
Podroid unpacks assets/iris-messenger/*-overlay.tar at /
on the persistent ext4 volume
    |  -- This is /var/lib/podroid/upper inside the VM
    |  -- The tarball contains:
    |       etc/init.d/iris-pod        (OpenRC service)
    |       usr/local/bin/iris-pod-start.sh
    |       etc/iris/runtime.env
    |
    v
OpenRC starts the default runlevel services
    |  -- podroid-bootstrap (kernel modules, cgroups, sysctl, ZRAM)
    |  -- podroid-network (eth0 up, default route, /etc/resolv.conf)
    |  -- podroid-resize (reads resize events from /dev/hvc1)
    |  -- podroid-hostd (host-bridge daemon)
    |  -- iris-pod  <-- our service
    |  -- podroid-ready (emits "Ready!" when boot complete)
    |
    v
iris-pod OpenRC service runs
    |
    +-- start_pre():
    |     - ensure /var/lib/iris exists with mode 0700
    |     - if iris-messenger image not in podman store yet:
    |         podman load -i /usr/local/share/iris/iris-messenger-arm64.tar
    |
    +-- start():
    |     - exec /usr/local/bin/iris-pod-start.sh
    |     - which runs: podman run --name=iris-messenger --detach
    |                   --network=host --userns=keep-id
    |                   -v /var/lib/iris:/var/lib/iris:Z
    |                   -v /etc/iris/runtime.env:/etc/iris/runtime.env:ro,Z
    |                   localhost/iris-messenger:arm64
    |
    v
iris-messenger container starts (~1-3s)
    |  -- generates /var/lib/iris/keystore/<iris-id>.ikpriv on first boot
    |  -- opens REST 9091 and WS 9092 on 0.0.0.0 (guest eth0)
    |  -- boots DLM federation if IRIS_DLM_BOOTSTRAP is set
    |
    v
Podroid's BootStageDetector matches "Ready!" in console.log
(state -> Running, auto-starts terminal bridge)
    |
    v
iris-android's MainActivity (single Activity, Compose, Hilt)
detects Running state via:
    - podroid's host-bridge (Unix socket) OR
    - adb logcat -s PodroidQemu:V (during dev) OR
    - The first successful curl to 127.0.0.1:9091/api/v1/health
        (we use this for resilience)
    |
    v
iris-android runs setup-podroid-forward.sh via ProcessBuilder
    |  podroid-forward add 9091 9091 tcp
    |  podroid-forward add 9092 9092 tcp
    |
    |  -- The guest's eth0 default gateway is 10.0.2.2 (QEMU SLIRP)
    |  -- The host loopback is 127.0.0.1
    |  -- The forward rule: 127.0.0.1:9091 -> 10.0.2.2:9091 (guest)
    |
    v
Smoke test
    |  curl -fsS http://127.0.0.1:9091/api/v1/health
    |  - if 200: continue
    |  - if fail: retry with backoff (1s, 2s, 4s, 8s, max 30s)
    |
    v
User sees the PairingScreen
    |  - shows 8-char Iris-ID (generated by IdentityStore.createIdentity())
    |  - input field for 6-digit code
    |
    v
User enters 6-digit code (from a peer or from setup wizard)
    |
    v
iris-android POSTs /api/v1/pair with {iris_id, auth_code}
    |  - iris-messenger container validates code
    |  - returns registration_token
    |  - iris-android stores it in EncryptedSharedPreferences
    |
    v
WS connection established (wss://127.0.0.1:9092/ws with Bearer token)
    |  - GatewayForegroundService keeps it alive in background
    |  - WorkManager handles reconnection on network changes
    |
    v
ChatListScreen renders / ConversationScreen ready
    |  - GET /api/v1/chats
    |  - WebSocket subscribes to incoming messages
    |
    v
Ready for 1:1 messaging, group creation, federation handshake
```

## Timing estimates (Pixel 6, QEMU TCG path)

| Phase | Time | Notes |
|-------|------|-------|
| APK install | 30s | first install, ~10s update |
| App icon -> VM start | <100ms | Podroid boots QEMU in onCreate() |
| QEMU TCG kernel boot | ~3s | Alpine 3.23 with custom kernel |
| OpenRC services up | ~1s | 6 services in parallel |
| iris-pod start_pre | ~50ms | mkdir + chmod + image check |
| podman load (first boot only) | ~500ms | OCI tarball extraction |
| podman run (container start) | ~1s | Python interpreter warm-up |
| iris-messenger keygen (first boot) | ~200ms | EC keypair in container |
| BootStageDetector -> "Ready!" | ~100ms | substring match in console buffer |
| podroid-forward registration | <50ms | QEMU hostfwd add |
| TOTAL cold start | ~5-7s | from icon tap to PairingScreen visible |
| TOTAL warm start (container cached) | ~4s | from icon tap (no podman load) |

## Failure modes and recovery

| Symptom | Cause | Fix |
|---------|-------|-----|
| Podroid VM doesn't start | AVF/pKVM not granted | `pm grant com.excp.podroid android.permission.MANAGE_VIRTUAL_MACHINE` |
| OpenRC fails to start iris-pod | iris-pod not executable | `chmod 0755` BEFORE tarring the overlay |
| iris-messenger container fails to start | Image not in podman store | Verify podman load in start_pre() returns 0 |
| `curl /api/v1/health` times out | iris-messenger still starting | Retry with backoff, max 30s |
| podroid-forward add fails | podroid-forward not in PATH | Run as adb shell run-as com.excp.podroid.debug |
| WS connection refused | Token not yet stored | Check EncryptedSharedPreferences write succeeded |
| 1:1 message round-trip > 1s | Federation not configured | Both pods need IRIS_DLM_BOOTSTRAP set or mDNS discovery |

## Verification commands (per step)

```bash
# After APK install, before opening
adb shell pm list packages | grep podroid
adb shell pm list packages | grep iris

# Right after opening the app
adb logcat -s PodroidQemu:V podroid-forward:V 2>&1 | head -30

# After ~5s
adb shell run-as com.excp.podroid.debug \
  curl -s http://127.0.0.1:9091/api/v1/health
# expect: {"status": "ok", "iris_id": "..."}

# After pairing (look for the token in iris-android logs)
adb logcat -s IrisGateway:V 2>&1 | grep -i "registration_token"

# After WS connection
adb logcat -s OkHttp:V 2>&1 | grep "WebSocket connected"

# Verify iris data is in the VM, not on Android
adb shell run-as com.excp.podroid.debug \
  ls files/upper/var/lib/iris/
# expect: keystore/  messages/  prekeys/  ratchet/

# Verify iris data is NOT visible to ADB
adb shell ls /sdcard/Android/data/com.excp.podroid/
# expect: empty or only app-private cache, NEVER iris keys
```
