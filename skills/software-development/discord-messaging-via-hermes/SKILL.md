# Discord Messaging via Hermes Agent

## Problem
Sending messages to Discord channels from within the Hermes agent environment requires understanding the available tools and their correct usage patterns.

## Solution
A reliable approach for sending Discord messages involves:
1. First checking available communication methods
2. Using the execute_code tool to run Python scripts that can interact with Discord
3. Formatting system reports or messages appropriately for Discord
4. Using environment variables or configuration for authentication

## When to Use
- When you need to send automated reports to Discord channels
- When posting system health checks, alerts, or status updates
- When integrating Hermes with Discord backup server infrastructure

## Step-by-Step Approach

### 1. Check Available Discord Methods
```bash
# List available tools to understand what's accessible
hermes tools list

# Check Discord-related skills
hermes skills list | grep -i discord
```

### 2. Prepare Message Content
Use Python to collect system data and format for Discord:
```python
import subprocess
import json
import os

def get_system_health():
    # Collect disk usage
    disk_result = subprocess.run("df -h / | tail -1", shell=True, capture_output=True, text=True)
    disk_parts = disk_result.stdout.strip().split()
    
    # Collect CPU usage (simple method)
    cpu_result = subprocess.run("top -bn1 | grep 'Cpu(s)' | sed 's/.*, *\([0-9.]*\)%* id.*/\\1/' | awk '{print 100 - $1\"%\"}'", 
                              shell=True, capture_output=True, text=True)
    
    # Check if key services are running
    hermes_result = subprocess.run("ps aux | grep -E '[g]ateway|hermes.*run'", shell=True, capture_output=True, text=True)
    ollama_result = subprocess.run("curl -s http://localhost:11434/api/tags 2>/dev/null || echo 'DOWN'", 
                                 shell=True, capture_output=True, text=True)
    
    return {
        "disk": disk_parts,
        "cpu_usage": cpu_result.stdout.strip() if cpu_result.stdout else "N/A",
        "hermes_status": "running" if hermes_result.stdout else "stopped",
        "ollama_status": "running" if ollama_result.stdout.strip() != "DOWN" else "stopped"
    }

def format_discord_message(health_data):
    return f"""🔧 **System Health Report**
📅 {subprocess.run(['date'], capture_output=True, text=True).stdout.strip()}

💾 **Disk**: {health_data['disk'][1]} total, {health_data['disk'][2]} used ({health_data['disk'][4]} used)
🖥️ **CPU**: {health_data['cpu_usage']}
🤖 **Hermes**: {health_data['hermes_status']}
🦙 **Ollama**: {health_data['ollama_status']}

*Auto-generated by Hermes Agent*"""
```

### 3. Send Message Using curl (RELIABLE)

**⚠️ DO NOT use Python `urllib.request` — Discord returns HTTP 403 (error code 1010)** due to Cloudflare blocking Python's default User-Agent. `curl` works reliably.

```bash
# Read token from .env
DISCORD_TOKEN=$(grep '^DISCORD_BOT_TOKEN=' ~/.hermes/.env | cut -d= -f2)

# Send to a channel by ID
curl -s -w "\n%{http_code}" \
  -X POST "https://discord.com/api/v10/channels/{CHANNEL_ID}/messages" \
  -H "Authorization: Bot $DISCORD_TOKEN" \
  -H "Content-Type: application/json" \
  -d "{\"content\":\"Your message here\"}"

# HTTP 200 = success
```

### 3b. Send Message Using execute_code (fallback via terminal)

If you must use Python (e.g., for escaping), shell out to curl:
```python
import subprocess, json, os

token = ""
with open(os.path.expanduser("~/.hermes/.env")) as f:
    for line in f:
        if line.startswith("DISCORD_BOT_TOKEN="):
            token = line.strip().split("=", 1)[1]

msg = json.dumps({"content": "Your message"})
result = subprocess.run([
    "curl", "-s", "-w", "\n%{http_code}",
    "-X", "POST",
    "https://discord.com/api/v10/channels/CHANNEL_ID/messages",
    "-H", f"Authorization: Bot {token}",
    "-H", "Content-Type: application/json",
    "-d", msg,
], capture_output=True, text=True)

print(result.stdout)  # last line is HTTP status code
```

### 3c. Outbox fallback (gateway pickup)

If the gateway is running, write to the outbox directory:
```bash
echo "Your message" > ~/.hermes/discord-outbox/dev-control-room_1485340236316807278.md
```

## Troubleshooting Tips

### Tool Availability Issues
If `hermes run-tool --tool discord` fails:
1. Check if Discord tool is enabled: `hermes tools list`
2. Enable if needed: `hermes tools enable discord`
3. Verify bot token is configured in environment

### HTTP 403 (error code 1010) from Discord API
- **Root cause:** Cloudflare blocks Python's default `urllib.request` User-Agent or datacenter IPs on some routes.
- **Fix:** Use `curl` instead (see step 3 above). Never use Python's default `urllib.request` for Discord API calls.

### HTTP 429 rate limits
- Discord can return route-specific 429s even during discovery or back-to-back `GET /users/@me/guilds` calls.
- Parse the JSON body, sleep for `retry_after + small buffer`, then retry.
- For bootstrap scripts, make REST helpers retry 429s before declaring failure.

### Permission Issues
- Ensure the bot has `Send Messages` permission in target channel
- Check that the channel ID is correct for the current server
- Verify you're operating in the correct Discord server context

### Message Formatting
Discord supports:
- **bold** and *italic* text
- `inline code` and ```code blocks```
- Emoji (both unicode and custom)
- Links (auto-preview or masked with <url>)

Limit messages to ~2000 characters for best results.

## Environment Configuration
Set these in your environment or `.hermes/.env`:
```
DISCORD_BOT_TOKEN=your_bot_token_here
DISCORD_WEBHOOK_URL=your_webhook_url_here
```
