## Discovery filtering pattern (validated this cycle)

**Two-pass filtering is more efficient than single-pass recall.**

1. **Pass 1 (orientation):** `mazemaker_recall(query="discovery:pulse-tick-", limit=50)` returns a mixed bag of decisions, facts, and discoveries. Useful for orientation + seeing which discoveries have been re-mentioned in today-rank context. But it pulls in many `decision:rank-*` entries that are noise when hunting for new discoveries.

2. **Pass 2 (precision):** `mazemaker_browse(label_prefix="discovery:pulse-wurm-2026062", limit=30)` returns ONLY discovery:* memories with that prefix — the cleanest possible filter for "what did this morning's pulse-wurm ticks save?". This is the actual discovery pool to score.

3. **Pass 3 (dedup check):** filter the full recall/browse output for `decision:rank-<today>-*` labels to know which discoveries are already-decided. Pattern: `[r for r in results if r.get('label', '').startswith('decision:rank-20260621-')]`.

**Why two-pass matters:** Recall's semantic ranking surfaces the "freshest most-mentioned" discoveries — but those are usually already-decided. Browse with label_prefix is mechanically precise — it gives you the actual chronological list of new discoveries. The two together let you score true novelty AND verify dedup in one workflow.

## Scoring formula (recap + numeric examples)

`score = connectedness + novelty + recency_weight`

Where:
- **connectedness** = count of top-10 recall results whose label starts with `fact:` or `decision:`, divided by 10
- **novelty** = 1 − max similarity to closest non-self memory
- **recency_weight** = freshness score (0.95 if <1h old, 0.65 if ~10h old, linear decay)

## Reusable technique (worth remembering for future DECIDE cycles)

When scoring novelties, the closest non-self memory isn't always the top result — `recall` returns self with similarity 1.0 (or the highest similarity). The actual "closest existing memory" is the SECOND result (or first result with id != target_id). Always filter self out before computing novelty = 1 − max_similarity.

Implementation: extract similarity from each result dict, sort descending, take second-highest (or first with id != target_id).
