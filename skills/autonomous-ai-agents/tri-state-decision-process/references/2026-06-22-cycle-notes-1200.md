## NEW patterns (worth adding to canonical SKILL.md)

### 1. Topic-recall verification before classifying a candidate as "unranked" (NEW — closes a coverage-detection gap)

The 2-hour dedup window checks whether the SAME discovery ID has been written as `decision:rank-*`. But the same TOPIC can be covered by a different discovery ID. Verified 12:00 UTC cycle:

- "iOS 27 Siri Extensions framework" topic → recall returned `decision:rank-20260622-0945-important-1-ios27-siri-open-extensions-framework-multillm-routing-2b-dev` (826262, 09:45Z) with primary discovery 826258. My candidate 826258 was the SAME discovery ID, so the dedup check would catch it — but the 2h dedup window is by label timestamp not by topic, and 09:45Z is OUTSIDE the 10:00-12:00 window. **Topic recall catches cross-window coverage that the time-window dedup misses.**

- "Polymarket Mythos US gov" topic → recall returned `decision:rank-20260621-important-3-anthropic-ipo-prediction-market-deadline` (825685, 2026-06-21). The PM addressed is different (IPO market $645K vol vs. Mythos-to-US-gov market, 0.596 score, $1M+ vol, different resolution criteria) — so my candidate IS unranked even though the cluster has prior coverage. **Topic recall distinguishes "same topic, different axis" from "same topic, same axis = duplicate".**

- "Nature AI ruining our skills" topic → recall returned `decision:rank-20260622-0446-nice_to_know-2-glp1-addiction-reduction-rscience-2026` (826151) which itself references 826140 as a cluster sibling. My candidate 826140 was COVERED — but the decision memory ID lives in the 04:46Z cycle, not the 2h dedup window. **Topic recall catches coverage from older cycles that the time-window dedup misses.**

**Diagnostic rule:** For each candidate, before classifying as "unranked", do a topic-specific `mazemaker_recall(limit=5)` and check if any returned `decision:rank-*` covers the same topic (regardless of label timestamp). If yes, verify the topic overlap is genuine axis-level (not just adjacent) and skip if so.

**Why it bites:** Without this check, the cycle would re-rank topics already covered by older cycles (outside the 2h dedup window). The 12:00 cycle avoided 4-5 false-positive re-ranks by running topic-recall verification on every 1st-order candidate (iOS 27, SpaceX, FERC, Anthropic cyberattack, etc.) before writing.
