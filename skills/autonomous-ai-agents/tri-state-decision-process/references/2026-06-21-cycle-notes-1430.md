## mazemaker_get for Individual Discovery Content (NEW — efficiency technique)

When `mazemaker_recall(query="discovery:*", limit=50)` returned only 1-2 actual discoveries (the rest were `decision:rank-*` because semantic recall biases toward densely-connected decisions), the right next move was **parallel `mazemaker_get(memory_id=N)` calls** for each candidate discovery, NOT a broader recall with different query phrasing.

**Pattern (PATCH AS A TECHNIQUE):**
1. Identify candidate discovery IDs from `mazemaker_browse(label_prefix="discovery:pulse-wurm-YYYYMMDD", limit=50)` — chronological browse catches everything for the day.
2. Filter by `created_at > (now - 2h)` to find eligible candidates.
3. Run `mazemaker_get(memory_id=N)` in PARALLEL (one tool-call block) for each candidate — gets the full content of 5-10 discoveries in <2s, with no recall-glob interference from decision:* neighbors.
4. Score each fetched discovery by running topic-recall against it (NOT against the discovery-pool-glob query).

This is faster + more accurate than repeated recall attempts with different query phrasings. The recall-glob pitfall (see `2026-06-21-cycle-notes.md` 03:30 UTC section) is sidestepped entirely when you switch to browse+get.
