### 2. Body-flagged CRITICAL ≠ DECIDE-classified CRITICAL (NEW — clarifies priority classification)

Discovery 826131's content explicitly flagged itself as "**CRITICAL**" in the body text. The 12:33 cycle classified it as IMPORTANT (with +0.30 priority boost), NOT CRITICAL.

**The distinction:**
- **Body-flagged CRITICAL** = the discovery's source/author flagged the finding as critical (e.g., phase trial primary endpoint met, supply-side structural change, "first-of-kind" event)
- **DECIDE-classified CRITICAL** = the DECIDE phase operator classified the discovery for immediate action per the priority buckets (security, data loss, blocking issue)

The DECIDE phase priority buckets are about OPERATIONAL URGENCY for the agent's own action queue, not about the discovery's source-level importance. A pharma supply-side game-changer is structurally IMPORTANT for the corpus (corpus value) and for downstream ACT-phase action (fact_memory creation), but it is NOT a CRITICAL blocking issue requiring immediate agent intervention.

**Decision rule:** When a discovery's body flags CRITICAL but the DECIDE phase priority criteria (security / data loss / blocking) don't apply:
- Classify as IMPORTANT with a priority boost scaled to the structural magnitude (e.g., +0.30 for tier-A supply-side game-changers like aleniglipron, +0.10 for tier-B academic findings like the 07:33Z aleniglipron rank)
- Note the body-flagged CRITICAL in the decision's "WHY IT MATTERS" section to surface the source-level urgency
- ACT phase then treats the IMPORTANT rank with the same urgency as a CRITICAL rank for fact_memory creation purposes

**Verified 12:33 UTC cycle:** 826131 was body-flagged CRITICAL but classified IMPORTANT with +0.30 priority boost. Total score ~2.25 — well above the typical IMPORTANT threshold (~1.8) and approaching CRITICAL-equivalent priority for ACT-phase scheduling.
