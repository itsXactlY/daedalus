### 2. Cluster-mate single-decision for small N siblings (REFINEMENT)

The existing cluster-representative selection rule (in SKILL.md) says: "When a fresh-direction pick produces N sibling discoveries, writing N separate decisions is write-only churn — same cluster, same pick, same score formula. The right pattern is rank ONE representative per cluster." I followed this for the 4-chiplet and 6-philosophy clusters in the 05:46Z cycle (per cycle-notes-0546).

This cycle refined the rule for SMALL N (2-3): when N=2 or N=3 siblings from the same tick/seed qualify AND the cluster's value lies in the COLLECTIVE inventory (e.g., "Lean 4 ecosystem: benchmark + framework + library"), write a SINGLE decision that names all N findings in the content. The decision is structurally a cluster-mate rank, not a representative rank. Two instances this cycle:

| Rank | Cluster | N findings | Single decision lists |
|------|---------|------------|----------------------|
| #2 | Lean 4 math/AI formalization | 3 | 826211 (SorryDB) + 826212 (Automated Conjecture Resolution) + 826213 (EconCSLib) |
| #3 | Dark matter direct detection | 2 | 826215 (Bootes III neutrino) + 826216 (black hole explosion gamma rays) |

**Why N=2-3 is different from N=4-6**: For N=4-6, the cluster is too large to inventory in one decision (the content becomes a directory, not a finding). The representative rule (pick 1) applies. For N=2-3, the cluster is small enough to inventory AND the siblings are distinct artifact types (benchmark vs framework vs library; neutrino channel vs gamma-ray channel), so listing them all adds axis-complementarity value.

**Future cycle guidance**: Distinguish three cluster sizes in the rule:
- N=1: single finding, write as single decision (default)
- N=2-3: small cluster, write as single cluster-mate decision that names all N (NEW refinement, this cycle)
- N=4-6: medium cluster, pick 1 representative using the existing heuristic (venue-anchor > mechanism-specificity > corpus-anchor)
- N=7+: large cluster, write 1 representative + create a separate cluster-survey fact_memory that inventories all N
