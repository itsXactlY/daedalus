## mazemaker_browse JSON structure ≠ mazemaker_recall JSON structure (NEW pitfall)

The "Oversized recall outputs" section of `decide-phase-runbook.md` documents the recall structure (`{"result": "[{...}]"}` — bare array). I assumed the same structure for browse and hit `'str' object has no attribute 'get'` on the first execute_code attempt because I was iterating over the inner JSON-string instead of the unwrapped `memories` list.

**The actual structure:**

```python
# Recall:  outer {"result": "[{...}, {...}]"}              # array directly
# Browse:   outer {"result": "{\"memories\": [...], \"count\": N}"}  # wrapped object
```

**Fix:** two-stage parse — `json.loads(raw)['result']` gives you a string; parse that string AGAIN with `json.loads(...)` to get the `{"memories": [...]}` object; then iterate `inner['memories']`.

**This is now patched into `decide-phase-runbook.md`** under a new section "mazemaker_browse has a DIFFERENT JSON structure than recall (verified 2026-06-21 17:16 UTC)". Future cycles following the runbook will see both recipes side-by-side and not make the same mistake.
