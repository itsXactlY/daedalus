## Login flow URLs (from `strings` on `GeneralsOnlineZH_60.exe`)

| Purpose | URL | Method |
|---|---|---|
| Version check | `https://api.playgenerals.online/env/prod/contract/1/VersionCheck` | HTTP GET |
| Login poll | `https://api.playgenerals.online/env/prod/contract/1/CheckLogin` | HTTP GET, polled every ~1s |
| Browser login (the URL the game opens) | `http://www.playgenerals.online/login/?gamecode={}` | ShellExecute |
| Update failure page | `https://www.playgenerals.online/updatefailed` | (only on error) |
| Match view | `https://www.playgenerals.online/viewmatch?match=%llu` | ShellExecute |
| Russia region | `https://api-ru.playgenerals.online/env/prod/contract/1/{}` | HTTP GET (alternative endpoint) |

`network.use_alternative_endpoint` in `settings.json` toggles between `api.playgenerals.online` and `api-ru.playgenerals.online`.

The `CheckLogin` response is `{"result":-1, "session_token":"", "refresh_token":"", "user_id":-1, "display_name":"", "ws_uri":""}` while waiting. Once user enters the code on the website, the next poll returns the populated session.

The login code is generated by the game and sent in the CheckLogin request. The server response body is `<redacted>` in the log, so the code is NOT visible from logs. The code IS visible in the in-game dialog (the first "Continue in browser" dialog, before the wait-state "Logging In" dialog appears). If the user missed the first dialog, click CANCEL on the wait-state, click Online again, and copy the code from the first dialog.

## Wine registry fix (URL → winebrowser)

```bash
export WINEPREFIX=/home/alca/Faugus/default
export WINE=/home/alca/.local/share/Steam/compatibilitytools.d/Proton-CachyOS\ Latest/files/bin/wine
"$WINE" reg add "HKCR\http\shell\open\command" /ve /d '"C:\windows\system32\winebrowser.exe" "%1"' /f
"$WINE" reg add "HKCR\https\shell\open\command" /ve /d '"C:\windows\system32\winebrowser.exe" "%1"' /f
"$WINE" reg query "HKCR\http\shell\open\command"
"$WINE" reg query "HKCR\https\shell\open\command"
```

`https` was already set by Faugus. `http` was empty and needed the same fix.

## Host-side browser fix — Firedragon-isolated wrapper (the working solution, June 2026)

**HARD RULE: NEVER touch Chrome on alca's machine.** See `security/never-touch-chrome-alca-machine` skill. The user runs Firedragon (`/usr/bin/firedragon`) as their daily-driver browser. Creating a chrome-wrapper.desktop, even with a non-launching pkill logic, is forbidden.

The fix is an isolated Firedragon profile wrapper:

`~/.local/bin/wine-browser`:
```bash
#!/bin/bash
# Wine-Browser-Wrapper: launches Firedragon in an ISOLATED profile.
# - Never touches the user's real Firedragon profile at /home/alca/.firedragon/*
# - Never touches Chrome (per HARD RULE 2026-05-22, memory id 479630)
# - --new-instance + --no-remote: do not interact with any running Firedragon
# - Profile lives in /tmp/wine-browser-iso/ — created on first use, ephemeral

PROFILE="/tmp/wine-browser-iso"
mkdir -p "$PROFILE"

if [ ! -x /usr/bin/firedragon ]; then
    echo "wine-browser: /usr/bin/firedragon not found" >&2
    exit 127
fi

exec /usr/bin/firedragon \
    --profile "$PROFILE" \
    --new-instance \
    --no-remote \
    "$@"
```

`chmod +x ~/.local/bin/wine-browser`.

`~/.local/share/applications/wine-browser.desktop`:
```ini
[Desktop Entry]
Version=1.0
Name=Wine Browser (Firedragon isolated)
GenericName=Web Browser
Comment=Isolated Firedragon launcher for Wine ShellExecute URL opens. Never touches the user's real Firedragon or Chrome profiles.
Exec=/home/alca/.local/bin/wine-browser %U
Terminal=false
Type=Application
Icon=firedragon
Categories=Network;WebBrowser;
MimeType=text/html;text/xml;application/xhtml+xml;application/xml;application/rss+xml;application/rdf+xml;image/gif;image/jpeg;image/png;x-scheme-handler/http;x-scheme-handler/https;x-scheme-handler/ftp;video/webm;
StartupNotify=true
```

**Then hand-edit `~/.config/mimeapps.list`** because `xdg-mime default` only updates `[Added Associations]`, not `[Default Applications]`. See `references/mimeapps-list-two-section-gotcha.md` for the full recipe. The Chrome-entries must be removed from BOTH sections in BOTH schemes (http, https, about, unknown, text/html).

Also run: `xdg-settings set default-web-browser wine-browser.desktop`

## What to NOT do

- Don't edit only the native Linux mirror `settings.json` and assume the game sees it. The prefix file is the one that matters.
- Don't run `wine reg add` with a wrong WINEPREFIX — it'll either silently apply to the wrong prefix or fail with a lock error if the game is running.
- Don't recommend `firefox` or `chromium` — neither is the user's daily driver. `firedragon` is at `/usr/bin/firedragon`.
- Don't restart the Faugus-launcher daemon for reg changes — they're written to disk and the next game launch picks them up.
- Don't trust old log files. Always check `ls -la` of both logs (native mirror and prefix) for the most recent mtime; the prefix log is the active one.
- **Don't create a chrome-wrapper.desktop.** Hard rule violation. The user's solution for the FUSE-PSD crash is a Firedragon wrapper, not a Chrome fix.
- **Don't rely on `xdg-mime default` alone.** It writes to `[Added Associations]` only; `[Default Applications]` (what most apps read) needs hand-editing. See `references/mimeapps-list-two-section-gotcha.md`.
- Don't `pkill` the user's running Firedragon in the wrapper. The user has live state. Use `--new-instance --no-remote` to launch a separate isolated instance.
- Don't `pkill` anything without first checking what processes it kills. The user's chrome-wrapper pattern (`pkill -9 -f 'chrome|chromium'`) is dangerous in shared environments.
