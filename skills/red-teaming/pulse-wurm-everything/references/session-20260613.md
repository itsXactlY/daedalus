# Pulse Search Session Patterns - 2026-06-13

## Observed Timing Patterns

### MCP Timeout Behavior
- `pulse_research` with `depth='deep'` times out at 120s consistently
- `pulse_research_start` spawns async jobs that stay "running" for 30-120+ minutes
- Even `depth='quick'` jobs can exceed 120s when `llm_filter=true` is enabled
- **Root cause:** Multiple phases (search→dig-1→dig-2→llm-filter) each take time; timeout occurs during LLM filtering phase

### Reliable Execution Patterns for Cron Ticks

**Pattern 1: Hybrid Approach**
```
1. Spawn async deep jobs: pulse_research_start(topic, depth='deep', ...) for 2-3 topics
2. Immediately run pulse_search(topic, depth='quick', llm_filter=true) for fast secondary results
3. Report on quick results while deep jobs continue in background
4. Next tick: check deep job status, potentially add more quick searches
```

**Pattern 2: Quick-Only Guaranteed Completion**
```
1. Use pulse_search without llm_filter for <60s completion
2. Or use pulse_search with restricted lookback_days (30-45) to reduce candidate pool
3. Supplement with pulse_dig on specific high-value URLs from results
```

### URL Quality Indicators
- **Keep:** `.pdf`, `arxiv.org/abs/`, `/article/`, `/news/`, direct article URLs
- **Skip:** `/tos`, `/privacy`, `/careers` - Polymarket boilerplate
- **Skip:** Language variants `/es/`, `/fr/`, `/de/` - Duplicate content
- **Skip:** `/api/og`, `/api/*` endpoints - Metadata, not content

### Engagement Thresholds
- Score > 500: Hot topic, viral discussion (e.g., AI agent job replacement posts)
- Score 200-500: Active community interest
- Score 50-200: Moderate interest, niche topic
- Comments > 50: Substantial discussion depth
